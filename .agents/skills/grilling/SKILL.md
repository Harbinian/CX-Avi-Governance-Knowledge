# 通用方案访谈

把待澄清的方案整理为决策树：区分已有决定、需要查证的事实，以及只有用户或有权主体能决定的分支。当前请求和已有授权已经确定的事项直接沿用。

每轮只提出前置条件已明确的问题。相互独立的问题可以同轮列出，依赖尚未回答问题的分支留到后轮。用编号、简短说明和建议答案组织提问，让用户回答“同意”即可接受建议，但不把沉默或“继续”解释为确认。

能够从获准材料、文件或工具中查到的事实先查证；可独立查证时继续处理不依赖该事实的分支。业务实际做法、责任和授权不能只从代码或示例推定。材料不足时说明具体缺口，不要求用户重复提供已有准确记录。

用户答复后，更新决策树和依据：明确哪些分支已经解决、哪些仍依赖事实或决定。一次局部答复不覆盖其他分支；冲突只暂停依赖部分。

当所有必要分支均已处理时，核对共同理解、成果范围和剩余假设。任务要求先确认方案再实施时，完成该确认后推进；已经明确确认的决定不重复询问。讨论结果不自动取得其他部门同意或公司批准。

与[领域建模](../domain-modeling/SKILL.md)组合时，在术语或决定明确后及时更新相应文档，并保留确认依据。具体单流程任务使用[本库grill-me](../grill-me/SKILL.md)，不以本方法替代其逐个问题和情景核验要求。
