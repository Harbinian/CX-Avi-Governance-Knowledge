# 续编、修正与交付模式

| 模式 | 处理 |
|---|---|
| 中断后继续 | 读取最新JSON、已完成成果及摘要，复用已确认目标、事实和设计；保留标识和问题号，不从头访谈 |
| 续编V7 | 保留源文件及真实归档；可以显式生成V8版本标识转换稿，但不声称规范化完成。3001导入差异及下载由用户处理 |
| 保存续接摘要 | 输出完整续接记录和需保存文件，不新增业务问题，不声称已在系统保存 |
| 按校验结果修正 | 用当前完整JSON、错误路径／代码／消息及确认修复可确定的问题；业务缺项按目标处理，不能通过删对象或猜值绕过 |
| 修改已确认决定 | 定位正文、行为、关系、字段、表单、贡献、评分和工时的影响；当前明确授权可直接应用，新的关键责任或权限仍需确认 |
| 只补工作量 | 只更新工作平衡报告，复用贡献及参数；流程改动先提出有据建议，不因评分高擅自删控制动作 |
| 阶段草稿 | 输出当前能表达的内容和缺口；无合法待定表示的内容留在Markdown，不能伪装完整最终包 |
| 完整待核对包 | 输出八章正文、完整V8 JSON、工作平衡报告及待确认事项，另保存问答及交接记录；明确未完成的量化结论和人工操作 |
| 更换目标结构 | 取得配套合同、模板和校验，比较兼容影响；旧源保留，转换另存，不只改版本号或自动降级 |

续编以最新下载文件为准；与旧摘要有冲突时先核对，不能用旧对话覆盖。用户认为当前对应范围符合事实后做事实核验，明确认可新设计方案后做设计情景推演，均按[会话规则](../../../../rules/process-session-rules.md)执行。设计逻辑、事实及授权分别记录，不将方案认可改成现状事实。

压缩、中断续接、工具切换或资料包换版后，按[读取边界](../../../../rules/material-reading-boundaries.md)重新读取主技能与当前规则，核对当前四项成果、稳定标识、已确认表示及其覆盖范围；重读不要求重复询问仍有据适用的事实。

交付前对JSON实际离线检查，正文与JSON双向核对，再核对报告行为贡献。技术只改一个对象也要检查受影响引用；纯文案不重跑无关应用测试。结构、评分和工作量输入没变的已通过结果可复用实际记录。

Word仅在用户要求时由同源Markdown生成，按指定模板或[格式规则](document-standard.md)检查实际呈现。送核对的清稿可以去掉内部技术标识和编制痕迹，但不得通过删除未知项制造完整性；未解决关键事实时交付阶段草稿，并保留独立问题清单。图件由用户从3000／3001选取插入，未插入不得说图件完成。
