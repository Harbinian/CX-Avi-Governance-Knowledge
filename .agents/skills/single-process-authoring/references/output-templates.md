# 四项成果与一致性复核

默认交付三份Markdown及一份完整JSON，辅助记录另存。文件名和技术标识使用英文；正文使用中文。所有成果关联同一`process_ref`、目标与修订，不能以文件齐全代替业务完整。

## A 八章制度正文

使用[正文模板](../../../../templates/process-procedure-draft.md)，默认包含目的、适用范围、术语和定义、职责、规定、流程、规定表格、记录控制八章。第5章写明主体、条件、动作、依据、完成标准、后续交接及实际存在的异常；第4章职责要能在第5章及JSON找到对应。第6章保留人工插图说明，图未插入时如实记录。

第7章逐张记录表单编号、名称、用途及载体，第8章记录留存部门、保管责任、期限及来源；未知项关联待确认清单。梳理实际流程时不推定载体、期限或编号。设计新流程时可给明确标注的方案，并说明约束、假设及尚需确认的事项；相近制度只能作建议参考，不能当成当前规则。受控编号须核对公司已确认的编号规则，不能借用编写规范自身编号。

拟新建表单在正文后附空白样张及字段要求，关联JSON的`forms`。字段类型、必填性、取值来源及办理关系依事实或明确设计填写；缺少布尔必填性依据且无合法待定表示时，留在Markdown，不猜填JSON。清稿可以去掉内部技术标识和编制痕迹，但须保留必要状态或单独问题清单，不通过删缺口制造完整性。格式见[制度规范](document-standard.md)。

## B 完整V8 JSON

新流程由`node scripts/validate-process.cjs --emit-template <新路径>`生成骨架，续编读取最新文件并保留稳定标识和数组顺序。按[结构规则](v8-structure-rules.md)填充，交付一个原生对象，不含接口包装、Markdown、注释或省略号。

不能表达的正式发文信息、保存期限、评分、工时、用户答复及确认记录留在配套Markdown，不塞入不相干字段。阶段稿未编码内容逐项说明，不能宣称已经完整编码。

在辅助记录中列出节点、业务行为、控制节点、关系、数据对象、字段、表单及待确认数量，记录实际技术检查和SHA-256。未运行时写未执行。`--expect-digest`只核对指定目标结构摘要，`--promote`只转换V7顶层版本标识，均不代替业务核对或3001规范化。

## C 工作平衡报告

使用[报告模板](../../../../templates/process-workload-report.md)，按[完整方法](workload-method.md)逐项填写。保留以下八部分：

1. 评价口径与覆盖范围：目标、周期、来源、方法、主体粒度、主责／协作计量及未覆盖工作。
2. 执行主体总表：贡献数、已评分覆盖、职责组合分、平均强度及完整或已知部分占比。
3. 行为贡献与逐维依据：关联`behavior_ref`，列出实际贡献、六维分值和来源；控制节点不当工作贡献。
4. 协作与典型路径：正常、退回及其他互斥路径分别列示，未确认比例不算期望负担。
5. 周期参数与情景：次数、每人分钟、人数、返工、固定工作、其他工作及容量，区分实测、估计、假设和待补。
6. 工时与容量：本流程人时、其他工作人时、有效容量、已计量覆盖、全岗位或专属容量口径；同一人时间和容量不重复。
7. 问题与建议：区分已知结构问题、实测结论及预测风险，不把职责集中或分数高直接说成过载。
8. 待补数据与有效性：评分、业务量、时间、人数、容量和来源缺项，说明限制及过期段落。

未知不填0或默认3分，分数不折算工时。仍可交付包含已知部分、待评和缺项的报告，不能为了凑齐完整四项成果虚构量化结果。

## D 待确认事项

使用[事项模板](../../../../templates/process-pending-items.md)。稳定问题号、类别、来源、关联条款和对象、需要回答的一件事、影响、所需依据及解决记录均保留；已解决不删历史，也不重新编号。

分别说明影响JSON完整交付的缺口、仅限制报告结论的缺口及尚未编码内容。其他部门事实或确认缺失也可登记，但不擅自指派人员、承诺时限或声称已通知。设计任务的拟议安排明确标为建议待决定。AI自身遗漏直接修正，不伪装为外部冲突；登记来源冲突前先取证，确有冲突时保留双方位置和适用性。

## E 双向复核

| 核对方向 | 核对内容 |
|---|---|
| JSON → 正文 | 名称、范围、角色、行为、条件、分支、交接、数据、字段、表单及未决内容是否准确表达 |
| 正文 → JSON | 已有动作、`trigger`、`timing`、`completion_standard`、退回／并行关系、`countersign_*`、字段引用是否已编码 |
| 正文中的无法编码内容 | 保存期限、正式编号及其他无对应字段的要求保留正文和事项清单，说明限制 |
| 业务 → 报告 | 每项贡献在真实行为或已确认协作中有依据，报告不遗漏已识别协作，不虚构工作 |
| 修订 → 四项成果 | 行为、条件、角色、字段变化同步受影响正文、JSON、贡献和参数；未复算段落标为过期 |

技术标识只需满足合同，文件编号及表单编号还须有公司编号依据。已确认设计、事实核验、离线技术校验、3001页面检查和3000正式办理分别记录。辅助的[任务记录](../../../../templates/process-task-record.md)和[交接记录](../../../../templates/process-handoff-record.md)不替代四项成果。
