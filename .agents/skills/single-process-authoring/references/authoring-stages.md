# 编制目标、阶段与状态

## 启动时明确目标

“首次／继续”描述会话起点；“梳理实际流程／设计新流程”描述业务目标，两者分别记录。旧摘要已明确目标时复用，不重复问；目标改变时说明哪些事实、建议和评价需要重新核对。

梳理实际流程时，材料要求、实际做法与二者差异分别记录，不能用一个方案消除现状缺口。设计新流程时，先识别已有制度和权限约束，再提出拟议动作、条件和角色；建议、编制方选择、有权确认分别记录，不能自动升级状态。

未知保存期限、表单编号、载体、布尔必填性或审批权不能用相近例子补成已确认值。设计任务可以提出明确标注的方案；涉及现行强制约束或关键授权时，需要相应依据或确认。缺口只影响依赖它的内容，不阻挡其他安全整理。

## 七阶段

| 阶段 | 需要明确的内容 | 本轮可检查结果 |
|---|---|---|
| 1 基本信息 | 会话起点、业务目标、材料、最新文件、版本、process_ref、输出目录 | 读取范围和当前基线清楚 |
| 2 流程边界 | 目的、适用对象、起止条件、归口、成功成果及不包含的范围 | 单流程范围可说明，未知分类不猜填 |
| 3 骨架与角色 | 谁做什么交给谁，实际办理与控制节点，各主体动作及授权来源 | 主线有据，关键角色不悬空 |
| 4 条件与异常 | 触发、前提、时限、完成标准、分支、退回、并行、会签和例外 | 条件有去向，退回有恢复位置 |
| 5 数据与表单 | 数据对象与字段、表单分区与引用、取值方式、具体创建／读取／更新 | 引用可追踪，更新范围有依据 |
| 6 交接与工作平衡 | 双方交付及接收标准、协作贡献、六维依据、周期次数和容量 | 业务交接与量化评价分开；未知参数明确 |
| 7 复核与交接 | 四项成果双向一致、问答核验、技术检查、未决及人工交接 | 实际通过项、缺口、过期结果和状态明确 |

阶段是依赖顺序和遗漏检查，不是七次重复审批。首次执行本库grill-me；续编复用最新材料，在用户明确认为本版对应范围符合事实后提问核验。详见[会话规则](../../../../rules/process-session-rules.md)。

新设计得到用户对当前方案的明确认可后，逐个情景推演方案逻辑、已知约束和角色边界；授权不足与假设待验证分别记录，不标成实际事实已验证。关键方案改变后重新取得认可并推演受影响部分。

## 状态与确认

| 状态 | 说明 |
|---|---|
| 现有事实 | 可定位材料或实际做法说明，保留来源适用性 |
| 设计建议 | 尚未确认的拟议安排，不作现状表述 |
| 已确认设计 | 有权主体明确确认相应安排；不能延伸为公司已经签发 |
| 待确认／待对齐 | 依据不足或存在差异，保留问题、影响和取证路径 |
| 待评／待补 | 评分或周期参数不足，不填默认中值或0 |
| 技术通过／待复验 | 实际技术检查状态，不代替业务核对 |

部门正式评审和3000审核在相应受控路径进行，编制技能不代办。缺少其他部门事实时可以记录缺口和所需依据，不擅自指派确认人、发送通知或写成已同意。AI自身遗漏直接修正，不伪装成外部冲突。

## 续接摘要

保留业务目标、当前阶段、文件及修订、process_ref和稳定对象标识、已确认事实与设计、来源、问题号、未编码内容、评分和工时参数、已过期成果、grill-me模式及覆盖范围、用户事实表示对应版本、实际检查和下一条关键问题。摘要须由使用者保存，不表示3001自动持久化。
