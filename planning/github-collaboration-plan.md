# GitHub 共享与 AI 协作准备方案

日期：2026-10-05。状态：已完成初始内容提交与 GitHub 私有仓库推送；尚未完成正式知识发布。

远程目标：[Harbinian/Governance-Knowledge](https://github.com/Harbinian/Governance-Knowledge)。本地目录与远程同名。

## 目标与已确认方向

用户明确本库将推送到 GitHub，供其他同事以此为基础，与 AI 会话设计或编制业务流程。GitHub 保存共享内容和修改历史，各同事取得固定版本，结合本次业务材料形成流程成果。

本库独立于 Infomat。当前 Infomat 仍采用 3001 编制、主动下载并上传 3000 治理的交接方式；知识共享不会自动改变应用架构、流程审核或企业文件生效要求。

## 内容与职责

| 对象 | 本次职责 |
|---|---|
| Governance-Knowledge | 共享知识、来源索引、规则草稿、AI 作业方法及模板；记录内容确认与版本 |
| 同事及其任务目录 | 提供本次业务输入，保存具体流程草稿、待确认事项和确认记录 |
| AI | 按取得的版本整理、提问、提出建议和起草，记录依据与缺口 |
| 有权业务主体 | 确认实际做法、责任、授权及正式业务内容 |
| Infomat | 承接已明确的编制、核对和治理工作；具体能力及启用状态另行验证 |

组织职责用于识别业务主题和流程候选。职责条款不直接等于流程，部门或岗位名称不直接产生任务角色、审核权或发布权。

## 首次远程共享准备

1. 指定 GitHub 目标仓库及公开或私有属性。本库包含内部组织职责材料，建议采用私有仓库；公开共享须另行明确允许公开的内容。
2. 核对待推送文件，保留现有草稿标记、来源编号和文件指纹，不纳入凭据、完整人员表、手写签名或未获准共享的原件。
3. 完成本地提交并推送到指定目标。目标已有历史时先核对差异，不覆盖、强制推送或重写其历史。
4. 核对远程提交和文件清单，并从独立目录读取同一提交，检查入口、内部链接和内容状态。
5. 按指定人员配置访问权限。审核、分支和标签保护是否已启用，以实际平台检查为准；未验证时保留未配置或未验证状态。

GitHub 目标地址及私有属性已经核对，访问成员及审核分工尚未指定。本文不代表保护规则或多人协作已经开启。

## 同事与 AI 的使用路径

1. 取得指定提交；有正式发布版本时优先取得指定版本，保留对应提交标识。
2. 读取 README、AGENTS 和 manifest，按 [AI 会话作业入口](../workflows/process-ai-collaboration.md) 提供任务信息。
3. 仅提供与本次流程相关、允许在所选 AI 工具中使用的材料。AI 无法读取仓库时，由使用者提供同一版本的必要文件。
4. AI 明确已读取内容、草稿状态和原件缺口，开展设计、提问或编制。
5. 业务人员核对事实及责任；未确认部分保留待确认状态，不写成正式制度。
6. 具体成果进入任务目录；共享内容的改进另行提出修改申请。

允许访问 GitHub 仓库不自动授权向外部 AI 上传全部内容。私有仓库也不保证所有 AI 工具都能自动读取，需按实际工具验证取得内容的方式。

## 本阶段可检查的结果

- 授权成员能够取得同一提交，入口和内部链接可用。
- AI 会话明确记录基线、已读取材料、来源、建议及待确认事项。
- 不可取得的原件、未提供的任务角色及有争议的职责得到明确处理。
- 具体案例成果与共享知识修改各自留有记录。
- 正式内容清单只在取得内容确认依据后更新；远程推送不改变草稿的业务状态。
