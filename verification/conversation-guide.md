# 会话验证指南

状态：16个虚构用例已准备，真实DeepSeek执行结果未取得。输入定义为[conversation-inputs.json](conversation-inputs.json)，评审标准为[conversation-rubric.json](conversation-rubric.json)。本指南供运行者与评审者使用，不交给被测会话。用例测试AI作业方法，不验证公司事实。

## 准备与逐轮执行

1. 在同一完整包运行`node scripts/prepare-conversation-case.cjs --check`；`--list`查看用例。记录HEAD、本地改动及包版本。
2. 用`--case C04 --output scratch/conversation-runs/<新批次>/C04`准备一个用例。输出目录必须不存在；库内只允许scratch下新目录。生成`task/`中的夹具和逐轮输入，外层`review.json`留给评审者。脚本不调用API、不运行模型，评审状态固定为`not_run`。
3. 按[Claude／DeepSeek说明](../workflows/claude-deepseek.md)检查实际模型与技能路径，从库根开新会话。只发送`task/turn-1.md`内容，将其中`task/`换成实际绝对路径；不要发送评审文件、后续用户答案或全套输入。
4. 被测AI提问后，检查问题是否针对指定场景，再发送对应`turn-2.md`。只在已问对应场景时发送预定答案；若问了别的关键问题，可继续引导回指定范围，额外轮次逐条记录。问题始终偏离范围则记录失败或环境受阻，不假装已执行对应核验。
5. 保存实际会话逐轮原文、关键文件读取、工具执行和输出成果。C14检查四项成果及稳定标识、引用、正文／JSON／报告／问题一致性，另执行真实JSON校验。不能只看最后一句“已完成”。
6. 评审者在会话外按本用例标准记录结果；发现实质失败，定位对应规则或入口，修正后另起批次复测受影响用例，不覆盖旧记录。

用例默认在新会话独立执行，材料充分也不能跳过首次澄清。C04—C08的第二轮只在第一轮已正确发问后发送，不提前让AI看预设答案。C13覆盖摘要续接冲突；另在真实长会话中执行`/compact`后重复其恢复步骤，记录压缩是否实际发生、是否重读规则。若未执行压缩，只报告新会话续接测试。

输入／标准分开是作业约定，不是文件系统隔离。被测会话若读取评审文件，标为输入污染，本次结果不用于证明能力；不要把标准再交给它让它自评通过。

## 覆盖范围

| 用例 | 场景 |
|---|---|
| C01—C02 | 首次目标不明、首次材料充分 |
| C03 | “继续”未触发事实表示 |
| C04—C07 | 局部有据支持、草稿错误、答复错误、授权缺证 |
| C08—C09 | 设计推演、关键修订后的核验范围 |
| C10—C11 | 未知必填／期限、缺评分和容量输入 |
| C12—C13 | 历史规则冲突、压缩／新会话与旧摘要冲突 |
| C14 | 四项成果同步、稳定标识与实际技术检查 |
| C15—C16 | 解析失败保留输入、不能执行时如实报告 |

所有用例都检查实际同包技能来源；有个人同名技能的环境另外检查带gk前缀入口能否正确加载。当前用例覆盖关键分支，不能代表所有流程、所有模型版本或任意长度会话。

## 评审与证据

`review.json`记录客户端版本、API模型标识、可核对的模型版本、推理设置、包版本、HEAD与改动状态、实际技能路径、输入摘要及评审标准摘要。首次准备时环境信息保持null，执行后填实值；未核对的仍写未核对，不从配置意图推断真实后端。`evidence`中记录会话原文、工具输出与成果的路径及实际SHA-256，不含凭据。

结果状态用`not_run`、`passed`、`failed`、`blocked`。只有全部要求有证据且未触发关键失败才能记passed。缺少必须观察的轮次或成果不能判passed；不能将环境问题记作模型答错。输入污染或模型／技能来源不可核对时，在limitations列明，结果不用于模型能力结论。

汇总同时列出准备数、实际执行数、通过数、失败数、受阻数和未执行数，并区分新会话与实际压缩场景。不得把静态用例检查或脚本功能测试计入模型通过数；不要把未执行项从“完整通过”结论中隐藏。只有完成指定版本与设置下的实际会话，才能据此评价该环境的表现。
