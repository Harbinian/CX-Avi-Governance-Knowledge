# 离线校验与3001／3000人工交接

本包提供固定技术快照和离线检查，供准备流程草稿。它不连接业务数据库、不自动上传、不审核发布，不能单凭本地通过保证目标3000已经具备办理条件。

## 在同事电脑上检查

离线校验需要本机已安装Node.js（18或更新版本；本次实际测试版本记于verification）。使用者运行以下命令时，工作目录为收到的资料包根目录。不需要Infomat仓库、Git或npm依赖安装，也不需要启动3000／3001。

```powershell
node scripts/validate-process.cjs --check-snapshot
node scripts/validate-process.cjs --emit-template "本次任务目录/流程-process-v8.json"
node scripts/validate-process.cjs "本次任务目录/流程-process-v8.json" --json
node scripts/validate-process.cjs "本次任务目录/流程-process-v8.json" --expect-digest <目标结构SHA-256> --json
node scripts/validate-process.cjs --promote "本次任务目录/旧V7.json" "本次任务目录/新V8.json" --json
```

`--emit-template`明确创建新骨架，生成新技术标识及实际时间，拒绝覆盖已有文件；仅在首次新建时使用。继续编制直接读取最新文件，不重建骨架。templates中的空白JSON仅示范结构，不直接复用其标识和时间。

普通校验读取一个UTF-8 JSON文件，最大10MiB，输出版本、结构摘要、源文件SHA-256及错误路径，不修改源文件。`--expect-digest`接收64位SHA-256，摘要不符也返回1。退出码0为技术通过，1为结构、语义或指定摘要核对失败，2为用法、输入或快照错误；均不能单独判业务对错。兼容输出`package_version`指技术快照版本，完整编制包版本另见manifest。

`--promote`仅接受V7，另存时只改变顶层schema_version，保留真实migration来源、稳定标识、全部内容及数组顺序，拒绝覆盖。输出明确标识为版本标识转换，不能表示迁移完成；转换稿有技术错误时仍另存并返回1，须修复或在3001核对规范化，不能将文件存在当成通过。

需要自行复查包的完整性及合成测试时，可运行`node scripts/check-package.cjs`和`node scripts/test-offline-package.cjs`；两者不连接业务系统。与Infomat来源比较的维护者测试才需要显式加`--source <Infomat目录>`。

先修复有据可修的问题，再检查受影响文件。不能为通过删除冲突对象、清空引用或虚构业务值。快照校验失败时取得同版本完整包，不绕过检查拼用不同版本。没有可运行的Node环境或AI不能执行命令时，说明“未执行”，可继续内容起草，并由使用者另行运行或在3001检查。

## 交接前的业务内容

八章正文、JSON、工作平衡报告和待确认事项保持同一最新修订，辅助问答记录另存。首次有grill-me澄清；续编在用户表示本版符合事实后核验答案；新设计认可后有设计推演记录。关键修改后重新核对受影响范围；设计核验不能写成现状事实已验证。

双向核对正文与JSON。JSON已有的行为、条件和角色应在正文准确表达；正文已有的时限、会签、退回与字段应在JSON相应字段编码，无法编码的控制说明保留正文并说明限制，不塞入不相干字段。记录实际结果到 [交接记录](../templates/process-handoff-record.md)，不能预填“通过”。

核对报告的主责／协作贡献与行为对应，评分依据及周期参数可追溯，工时、人数及容量不重复计量。缺少量化输入时交付已知部分和缺项，不能虚构满覆盖或负荷结论；影响JSON表达的关键业务缺口则明确为阶段草稿。

## 用户在3001主动操作

1. 核对目标3001的当前结构版本、实际运行状态及`/api/schema`摘要。V8结构应与本包快照一致；相同结构摘要仍不能单独证明语义规则或整个应用版本相同。
2. 主动导入完整JSON，核对旧文件升级或规范化差异、图、行为、条件、角色及表单字段。
3. 执行页面技术检查，阅读业务提示，分别记录错误、提示和待确认事项。能下载草稿不代表检查通过。
4. 主动下载当前“未审核”文件，核对实际文件名、版本、SHA-256及重导后内容；保留本次文件和记录。页面编辑只有主动下载才取得可恢复文件。

3001保持独立、无状态，不向3000自动提交，AI也不替用户上传。没有实际导入、下载和重导证据时，只能报告离线准备完成。

## 用户在3000上传与治理

先由实际接收人员核对目标3000当前支持原生V8、预览及正式办理入口是否开启、有效部门与本人权限。健康接口可用只能说明进程状态，不能代替上述条件。

首次上传建立相应流程案例；续编上传原案例的新修订并保留原process_ref。3000重新执行共享校验，并核对归口、跨部门事实、未解决卡口及修订摘要。相同名字不能证明同一案例，资料包不能自行决定部门映射。

按3000受控路径办理核对、正式提升、提交、审核及发布；不能用用户在AI对话中的表示替代其他部门确认或有权审核。正式发布后取得process_version_id，后续治理绑定该正式版本；数据对象身份、主数据认定、关键字段和正式生命周期由MDM工作组按既有职责办理。

目标未开启、角色权限或有效部门不符时，保留草稿及错误记录，暂停相应系统交接。没有当次证据不声称已开启、已接收或已验收。
