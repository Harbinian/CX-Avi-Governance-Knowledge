# 与 AI 会话设计或编制流程

状态：共享起步作业方法，供草稿协作使用；不代表公司流程规则或派生知识条目已批准生效。

## 开始前的准备

取得固定 Git 提交或指定发布版本。每次任务保持同一基线；需要换版时说明变更及影响，不在会话中静默切换。

准备本次流程名称或业务主题、工作目标、起止边界、现有材料及实际做法说明。已确认的责任和授权注明依据；暂缺的信息保留待确认，不用岗位名称补齐。

当前 `manifest.json` 的正式有效清单为空，可引用已登记来源和派生草稿开展提问、设计及起草；不得声称采用了本库正式发布的知识基线。制度是否现行与派生摘要是否经确认是两个状态。

## 可复制的会话启动文本

将方括号内容替换为本次信息，未提供的信息写“未提供”。不得填写假设的提交或发布版本。

```text

仓库地址：[实际 GitHub 地址或本地目录]
固定基线：[完整 Git 提交标识；有正式发布版本时同时记录版本]
本次目标：[流程设计 / 编制流程正文 / 修订既有草稿]
业务主题或流程名称：[填写]
起止边界及预期结果：[填写]
本次材料及确认记录：[列文件、来源、适用日期和可定位内容]
已确认的责任和授权：[填写或写未提供]
成果保存位置与格式：[任务目录；指定需要的格式]

先读取 README.md、AGENTS.md、manifest.json 和
workflows/process-ai-collaboration.md，再按任务读取相关知识、来源及模板。
若不能直接读取仓库，请说明需要我提供的文件，不假装已经取得内容。
请先说明实际读取的基线、材料状态、已知事实和影响本次工作的缺口。

区分来源事实、实际做法、分析判断、改进建议和待确认事项。
不要将部门职能、职务名称或配置参考自动转换为任务角色、审批链或权限。
摘要不能替代原件的完整条件；需要具体条件时明确回查位置。

按任务完成可推进的整理、提问、设计或起草；仅暂停依赖缺失依据的部分。
新流程方案中的建议做法要标为建议；有争议的制度要求与现状分别记录。
输出成果、来源定位、待确认事项及适用限制，保留草稿状态和确认记录。
不要自动修改共享知识库、写入业务系统、发布内容或发送通知。
```

## 按任务读取

| 任务需要 | 对应材料与处理 |
|---|---|
| 识别部门业务主题 | 读取部门职能摘要及来源定位，提出流程候选；不把每条职责直接变为一个流程 |
| 判断组织边界 | 读取组织架构及待确认事项；名称和对应关系存在争议时保留差异 |
| 参考岗位配置 | 读取岗位配置参考，保留参考属性；涉及具体任务分工时取得另行确认 |
| 起草完整流程 | 提供触发、输入、步骤、结果、交接及异常处理的实际材料；缺口转为问题或明确标注的建议 |
| 修改既有流程 | 提供原草稿、修改要求、已有确认记录及影响范围，核对需重新确认的部分 |
| 生成结构化文件 | 提供目标工具支持的现行结构规则、样例或校验入口；没有规则时不自拟字段并宣称可导入 |

本库当前未提供 3001 导入 JSON 的完整结构规则或校验器。需要该格式时应使用目标工具的现行规则另行编制和校验，不能仅凭组织知识推断其格式。

## 成果与共享更新

具体任务成果保存到用户指定的任务目录，记录固定基线、材料定位、内容状态和待确认事项。业务人员核对事实及责任，正式审批和生效按相应受控程序办理。

发现共享知识存在错误或缺口时，按 [贡献说明](../CONTRIBUTING.md) 提出 [修改申请](../templates/change-request.md)。本次流程建议不会自动成为全公司通用规则。

当前 Infomat 交接方式仍为 3001 编制、用户主动下载后上传 3000 治理。实际能力、正式启用和业务验收以对应任务的证据为准。
