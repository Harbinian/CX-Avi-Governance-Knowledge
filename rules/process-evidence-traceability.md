# 流程依据追溯与修订影响

本规则用于流程编制、续编和交付复核，依据见[方法升级记录](../sources/method-upgrade-confirmation-2026-10-13.md)。它补充AI作业方法，不改变公司职责、审批权限、JSON合同或正式审核门槛。事实与设计判定仍按[会话规则](process-session-rules.md)，完整性评价仍按[内容复核规则](process-content-review.md)。

## 1 区分来源登记与实际取得

在[任务记录](../templates/process-task-record.md)中给本轮实际使用的材料或业务说明分配稳定来源号，记录版次、适用范围、具体定位及实际取得情况。来源号只用于任务记录，不新增到流程JSON。

| 实际取得情况 | 可以支持的说明 |
|---|---|
| 已读取原件或获准摘录 | 记录实际读取范围、页码／条款／字段／记录位置；摘录不能证明未提供部分 |
| 已取得明确业务说明 | 记录说明者、时间、范围及原答复或准确摘要；说明不自动证明其具有审批或授权资格 |
| 仅取得派生摘要 | 说明摘要来源及限制；需要原件支撑的条件、权限或争议结论保留缺口 |
| 已登记但不可访问／未取得 | 保留获取路径和受影响结论；文件路径存在于清单不等于已读取内容 |

只在实际计算时登记SHA-256；摘要证明文件身份，不证明内容正确或业务有效。原件不可访问时，继续处理已有依据支持的内容，不自动复制受限材料或改用历史文档代替。

## 2 让关键结论关联依据与成果位置

关键结论包括会影响流程边界、动作、条件、角色与权限、交接结果以及报告量化结论的事实或设计。按实际需要在任务记录中关联：结论号 → 来源号及具体支持位置／确认记录 → 正文、JSON、报告或待确认事项位置。

- 同一来源可支持多个结论，一次登记后复用；同一结论有多项依据时保留各自支持范围。
- 明确区分事实、已确认设计、建议和待确认事项。只有结论与草稿一致，不能记为依据已充分。
- 存在冲突时保留双方位置、版次和适用范围；缺证、未知或无法编码的内容关联稳定问题号及影响。
- JSON位置使用既有稳定标识和字段，正文及报告使用章节／表格／行定位。没有对应内容时写不适用或尚未编码，不虚构关联。
- 用户认可设计、模型回答或实现行为不能代替有权主体确认。岗位配置参考不能单独支持任务授权。

不逐句建立映射；优先记录会改变办理、责任、约束、交接及结论的内容。已有问答或反馈记录能准确定位时直接引用，不重复抄写。

## 3 四项成果按同一修订复核

交付前固定最新四项成果及修订，在任务记录中列出关键对象的对应位置和实际差异。按[四项成果说明](../.agents/skills/single-process-authoring/references/output-templates.md)双向核对：

| 改变的内容 | 需要核对的关联 |
|---|---|
| 行为、角色或协作 | 正文职责与办理要求、JSON行为及关系、报告贡献和参数、关联问题 |
| 条件、时限、异常或交接 | 正文控制要求、JSON可表达字段及去向、典型路径和报告假设、受影响核验场景 |
| 数据、字段或表单 | 字段来源及创建／读取／修改、JSON引用和表单、正文规定表格及记录、未编码事项 |
| 业务量、工时或容量 | 报告计算、覆盖和结论；未改变流程内容时复用原正文与JSON并记录其文件版本 |

JSON无法表达的要求保留在正文或报告，并在记录中说明限制、影响和待处理事项。格式不支持的内容不塞入不相干字段；不能为了映射齐全增加业务事实。

完成的说明分别记录内容复核、成果一致性、实际技术检查和人工交接状态。技术通过不自动关闭业务问题；已有核验只对其版本和范围有效。

## 4 修订、换版与提问复用

方法包版本、技术快照版本和业务材料版次分别记录。正在进行的任务保留原基线；换版前定位变化及受影响成果，不整套覆盖最新稿。来源变更不自动使所有内容失效，也不自动证明新来源适用于本任务。

每次关键修订记录改变对象、原依据与新依据、受影响成果、旧结论可复用范围和需要重新核验的场景。事实表示／设计认可的取得时点继续遵守会话规则；技术合同变化另按[交接说明](../workflows/process-handoff.md)核对兼容条件。

提问前检查已取得材料及答复。已说明且仍适用的内容直接引用；部分未知时只问剩余缺口，并说明它影响哪项判断。重复确认应有具体原因，例如新旧依据冲突、版本变化或权限尚无依据。必需的首次澄清及情景核验仍执行，不为减少轮次省略关键核验。

本规则中的表格复用已有任务、反馈和交接记录；没有对应事项时注明不适用，不另建无用途的台账。
