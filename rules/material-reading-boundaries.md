# 当前材料与历史材料的读取边界

本文件规定进入AI会话上下文的材料范围；会话时点仍以[会话规则](process-session-rules.md)为准。用户指定的原始业务材料和确认记录用于核对事实，目录位置、提交日期及文件名中的“规则”不赋予业务权威。

## 按任务逐步读取

| 材料 | 默认用途及读取条件 |
|---|---|
| README、AGENTS、manifest、会话作业入口 | 启动时核对当前包、范围、技能正文及任务目录 |
| `.agents/skills/`、`rules/`、`workflows/`、`templates/` | 当前作业方法；单流程任务先读主技能、会话规则及本文件，按阶段只读所需参考，不展开全部references |
| `.claude/skills/` | Claude Code调用入口；实际执行前读取其指向的同包方法正文，不能只看description |
| 用户指定的最新四项成果、问答与续接记录 | 恢复当前任务；旧摘要与最新文件冲突时定位差异，不直接覆盖最新稿 |
| `knowledge/`、`sources/organization-sources.md` | 按业务主题读取派生草稿和来源定位；不能从部门或岗位推定任务角色及审批权 |
| `technical/snapshot.json`、`technical/contracts/` | 需要JSON字段或兼容检查时读取对应版本和有关字段；旧结构仅为兼容依赖 |
| `technical/compiled-schemas.cjs`及校验运行模块 | 默认由Node执行，不整份送入提示词；维护校验实现时才读有关代码 |
| `sources/tooling-sources.md`、`sources/authoring-source-snapshot.json` | 维护、追溯或核对版本时读取来源元信息；目录和链接不授权自动展开历史正文 |
| `sources/skill-snapshots/**` | 原技能历史原文，只在用户要求追溯、定位冲突或维护者核对来源差异时读取指定文件和章节；不作为当前编制指令 |
| `planning/`、过去的`verification/`报告 | 建设历史和某次检查证据；不证明当前已上线、已验收或已经满足本轮条件 |
| `examples/`、会话验证夹具 | 虚构结构或测试输入，只在演示、验证任务或用户明确指定时读取；不带入真实业务 |
| 会话用例评审标准、评审结果 | 仅评审者或维护者读取；被测会话不得读取或用它生成答案 |

普通流程编制的检索限定在当前技能、规则、作业入口、相关模板及指定任务材料；不要用全仓`rg`把历史原文、全部报告和预编译代码一起加入上下文。维护者做文件清单、字节摘要和链接检查可以扫描这些文件，这种检查不使其成为执行规则。

## 确需读取历史时

先记明读取原因、具体路径／章节、来源版次及本轮用途。历史仅解释来源或差异；发现冲突，记录旧条款、当前要求和影响，以本轮明确要求及当前方法处理。没有当前业务依据时仍保留缺口，不从原技能补造保存期限、表单必填性、默认角色、业务量或容量。

当前[八章正文说明](../.agents/skills/single-process-authoring/references/document-standard.md)已给出适用的编制要求，其中原规范链接仅供追溯，不要求每次展开。历史原文保留原字节及SHA-256，不能为消除冲突修改原快照。

## 长会话和换版

发生压缩、中断续接、模型／工具切换或资料包换版后，重新实际读取当前主技能、会话规则和本文件，并核对用户指定的最新成果、版本及核验范围。已有内容完整且仍适用时复用；不能仅凭摘要宣称仍记得全部规则，也不能把旧核验结论套到关键修订后的版本。

任务记录保留实际读取的关键路径、包版本、技能来源、草稿修订和可计算的文件摘要；未读取、未计算或未执行的明确记录，不编造工具痕迹。以上是作业约定，不是自动拦截器；模型是否遵守须通过真实会话检查。
