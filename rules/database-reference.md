# 流程编制中的数据库知识引用

依据：用户于2026-10-22授权将用友、勤哲数据库知识接入本库，先完成来源盘点、字段级知识、流程引用和试点验证；授权范围及影响见[修改记录](../sources/database-knowledge-upgrade-2026-10-22.md)。本文件落实AI作业方法，不新增公司业务规则、人员责任或数据库访问权限。

## 来源与适用性

内部知识包必须记录实际取得的来源文件、摘要、对象或查询定位、采集时间及限制。文件摘要用于校对文件身份；在没有历史结果摘要的情况下，本轮补算摘要不能证明历史结果从未变动。Infomat的`docs/`仅用于寻找原始线索，派生报告不因复制而成为业务真源。

分别表达技术证据、业务含义确认和当前适用性。缓存结构、缓存视图、历史查询、样本统计和明确业务说明具有不同支持范围；其中一种已核对，不自动表示其余也已确认。未知状态、单位、枚举含义和权限不填默认值。

结构采集未记录架构、实例或账套边界时，保留缺口；不得凭对象同名并入已定位对象。`schema=null`的条目可作为查证线索，不能用于精确数据库字段映射。没有实际参数值或参数文件摘要时，不从邻近文件推定历史查询的账套、日期窗口或样本范围。

## 从业务需求查字段

按本次流程的数据需要检索相关主题，不把全量目录读入提示词。检索排序、同名字段和SQL标准结构都不证明公司业务含义。候选不唯一时列出差别，按实际依据选择；已经确认且适用的映射直接复用，只追问剩余缺口。

核对表与视图、主表与明细、工作项副本、历史版本和记录粒度。关联记录必须说明完整连接字段、类型转换、必要筛选、证据与限制；复合键不缩减成单字段，一对多不通过去重掩盖。用于一致性核对的等值表达不能自动改成推荐连接条件。

缓存视图的过滤、排序或例外分支只说明当时实现。不能据字段非空推定审批链已完成，也不能据名为“最新”的视图推定每个业务编号只有一条记录。若实现与已确认业务意图不符，记录偏差、影响和依据。

## 流程成果与精确映射

流程内`data_ref/field_ref`表示业务对象及字段，数据库目录另用`object_ref/field_ref`定位物理对象；两套标识不相互替换。正文说明来源和业务使用条件，JSON只用当前合同支持的`source_links`、`external_system`及既有引用字段，不新增顶层数据库目录或未声明字段。

精确映射另存[引用记录](../templates/database-reference-record.json)，记录流程文件摘要、知识包版本及manifest摘要、流程对象字段、数据库对象字段、证据号和映射确认情况。`user_confirmed_for_process`仅表示本流程使用者已明确说明该映射，需保留确认记录，不表示主数据权威、其他部门同意或公司批准。未知映射保持`pending_confirmation`。

更新流程或知识包后，重新核对受影响映射。通过引用检查仅表示文件身份、标识与引用可解析；语义正确性、业务授权和当前运行状态分别核验。JSON无法表达的来源条件保留正文及任务记录，不塞入不相关字段。

## 访问与共享

只采集本次授权的离线结构、获准的视图定义和明确列出的数字汇总，不读取连接配置、密码、令牌及人员或交易记录值。字段名称本身仅是结构；认证字段的默认值和原始值均不采集。组织和人员有效记录仍由3000维护，不从外部系统结构推定办理人或账号权限。

公共仓库保存方法、工具、格式和虚构测试材料。内部结构、真实映射、绝对来源路径和业务统计保存在Git忽略的`private/`，分享范围按实际授权核对。`.gitignore`防止常规暂存，不代替文件访问控制或内容审核；不得强制加入内部目录后推送。

同事通过Git取得方法与工具，内部包按[同步与领用](../workflows/database-knowledge-sharing.md)经受限渠道另行取得。接收者的包内摘要检查与发送者的原始来源核验分别记录；未取得原件时不宣称已重新核对来源。

本轮不启用实时查询、不连接正式库、不执行迁移、同步、通知或发布。将来接入只读查询时另核对目标、权限、结果范围、时间及审计；取得知识包不自动赋予实时访问权。
